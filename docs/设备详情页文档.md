# 设备详情页文档

本文说明桌面端设备详情的目录结构、渲染优先级，以及如何新增/修改品类预制 UI。

## 入口

- 路由：`#/devices/:id` → [`apps/desktop/src/pages/DeviceDetailPage.tsx`](../apps/desktop/src/pages/DeviceDetailPage.tsx)
- 品类组件：[`apps/desktop/src/devices/`](../apps/desktop/src/devices/)
- 类型推断：[`apps/desktop/src/lib/deviceMap.ts`](../apps/desktop/src/lib/deviceMap.ts)（按 `model` / 名称推断 `Device.type`）
- 统一导出：[`apps/desktop/src/devices/index.ts`](../apps/desktop/src/devices/index.ts)

详情顶栏会显示设备名、在线状态，以及完整型号：`model:<device.model>`（所有设备统一展示）。

## 渲染优先级

`DeviceDetailPage` 按以下顺序选择 UI（从上到下命中即停）：

1. **电脑开机卡**（`hipc.plug.*` / `type === 'pc-boot'`）→ `PcBootDetail`
2. **React 插件**（`userData/plugins` 下 `.jsx`/`.tsx` 文件名匹配 `device.model`，支持 `*` 通配）→ `PluginDetail`
3. **品类预制 React 页**（按 `device.type`）
4. **通用 Spec 页** → `GenericDetail`

| `device.type` | 组件 | 目录 |
| --- | --- | --- |
| `light` | `LightDetail` | `devices/light/` |
| `plug` | `PlugDetail` | `devices/plug/` |
| `air-purifier` | `PurifierDetail` | `devices/purifier/` |
| `camera` | `CameraDetail` | `devices/camera/` |
| `lock` | `LockDetail` | `devices/lock/` |
| `speaker` | `SpeakerDetail` | `devices/speaker/` |
| `scale` | `ScaleDetail` | `devices/scale/` |
| `ac` | `AcDetail` | `devices/ac/` |
| `massager` | `MassagerDetail` | `devices/massager/` |
| `pc-boot` | `PcBootDetail` | `devices/pc-boot/` |
| 其他 | `GenericDetail` | `devices/generic/` |

说明：品类页按 **type** 聚合，不按单个 model 建目录。例如 `yunmai.scales.ms107` 走 `type === 'scale'` → `devices/scale/ScaleDetail.tsx`。若某机型需要特化，可在对应品类目录下新增文件再在品类入口里分支。

## 共用模块（shared）

多数品类页会引用：

- `@/devices/shared/DeviceCapabilityPanel` — 从完整 Spec 渲染可读可写属性与动作；品类页底部「全部能力」也用它
- `@/devices/shared/DetailPowerButton` — 统一电源开关交互
- `@/devices/shared/detail.css` / `detail-power.css` — 通用详情样式

品类私有样式放在本目录（如 `scale/scale.css`），不要塞回 `shared`。

## 与 React 插件的关系

- 插件目录：Electron `userData/plugins/<id>/`，由主进程 HTTP 提供
- 安装方式：上传 `.zip`，自动解压；必须含 `config.json` + `index.jsx`/`index.tsx`
- 匹配规则：`config.match` 等于 `device.model`，或含 `*`（如 `yeelink.light.*`）；也可为字符串数组；精确匹配优先
- 资源：`config.logo` 等相对路径，代码内用 `miPlugin.assetUrl(path)`
- 管理页：侧栏「插件」→ [`TemplatesPage`](../apps/desktop/src/pages/TemplatesPage.tsx)
- 运行时：[`apps/desktop/src/plugins/`](../apps/desktop/src/plugins/)（`PluginDetail`、Sucrase 运行时 JSX）
- API：props `device` / `values` / `config` / `miPlugin`（含 `assetUrl`、`setProp`、`setSwitch`、`runAction`、`reload`、`toast`）
- 示例包：[`docs/plugins/yeelink-light-demo/`](./plugins/yeelink-light-demo/)

有匹配插件时**不会**再走品类 React 页（开机卡除外）。

## 如何修改现有品类页

以体脂秤为例（`yunmai.scales.ms107` 等）：

1. 改 UI / 筛选 / 历史 → `devices/scale/ScaleDetail.tsx`
2. 改趋势图 → `devices/scale/ScaleTrendChart.tsx`
3. 改样式 → `devices/scale/scale.css`

插座功耗图在 `devices/plug/PlugPowerChart.tsx`；音箱样式在 `devices/speaker/speaker.css`。

## 如何新增一个品类预制页

1. 在 `deviceMap.ts` 中保证该机型能推断出稳定的 `Device.type`（或扩展 `DeviceType`）。
2. 新建目录，例如 `devices/vacuum/VacuumDetail.tsx`（可加同目录 css）。
3. 需要 Spec 兜底或电源按钮时，从 `@/devices/shared/...` 引入。
4. 在 `devices/index.ts` 增加导出。
5. 在 `DeviceDetailPage.tsx` 增加分支：`device.type === 'vacuum' && <VacuumDetail ... />`，并把它从「走 Generic」的排除列表里处理干净。

## 相关引用

| 用途 | 路径 |
| --- | --- |
| 详情路由壳 | `pages/DeviceDetailPage.tsx` |
| 品类入口导出 | `devices/index.ts` |
| 开机卡本地任务调度 | `hooks/usePcBootScheduler.ts` → `devices/pc-boot/pcBootLocal.ts` |
| React 插件挂载 | `plugins/PluginDetail.tsx` |
| Bridge 属性/快照 | `api/bridge.ts`（`getSnapshot` / `setProp` / `getScaleHistory` 等） |

## 约定

- **按品类拆目录，不按单个 model 拆目录**；机型差异优先在品类组件内用 `device.model` 分支，或用 React 插件覆盖。
- 业务逻辑放在 `devices/<category>/`，路由壳只做分发与顶栏。
- 不要把品类文件再塞回已删除的 `pages/details/`。
